Authority model

what the model may and may not do

The model can

  • ✓ Read and understand customer messages
  • ✓ Extract commitments — amount, date, intent
  • ✓ Cite verbatim evidence for every claim
  • ✓ Propose a structured recovery action

The model cannot

  • ✕ Change a balance or write a ledger entry
  • ✕ Mark an invoice paid
  • ✕ Issue a discount, refund or write-off
  • ✕ Contact someone who opted out
  • ✕ Execute a Tier-2 action, or approve its own
The last two are structural, not policy text. The action catalogue has no discount, write-off or mark-paid member, so the model cannot express them; and no role in this system holds UPDATE on a recovery action, so nothing — model or otherwise — can move an action out of pending approval.
All figures are read back from the ledger after committed deterministic code wrote them. The model proposes; it never writes money.
Payment confirmation is read from Razorpay Test Mode and reconciled through the same deterministic ledger used by the simulator. Test Mode is a provider sandbox — no real money moves, and no production Razorpay integration is claimed. The simulator path is local deterministic simulation with no external payment provider. Recovery data is synthetic.
